## 三、★ 但它引入了一个**真缺陷**（我判定：应当回退）

### 缺陷：把"手在哪"从【精选入口】退化成【目录倾倒】+ 删掉原精选清单

**证据**：
```
$ node scripts/self-dev-brief.mjs | sed -n '/## 三、手在哪/,/## 四/p'
- `node scripts/ablate-l3.mjs <args>`　—— 
- `node scripts/add-preset-council.mjs <args>`　—— 
...
- `node scripts/check-all.mjs <args>`　—— 常驻守卫总入口
（共 165 行；role 非空的只有 6–8 条；**每条 cmd 都硬拼了 `<args>`**）
```
且：
```
$ grep -n 'TOOL_SPEC' scripts/self-dev-brief.mjs
142:const TOOL_SPEC = Object.entries(TOOL_ROLE_MAP).map(([id, role]) => ({ id, role }))
```
⇒ **`TOOL_SPEC` 成了死代码**（buildBrief 里根本没引用它）——
**原来那份 8 条精选入口（task-bank / arm-up / run-experiment / …）在整个简报里消失了。**

**为什么这是缺陷（不是口味问题）**：
1. **与用户的原话相反**。用户要的是 *"告诉它我们**有哪些**，就是你在开发过程中写的这些文档"*
   —— 是**我们写的、有意义的那些**；不是 `scripts/` 的目录列表。
   165 条里 159 条 role 为空 ⇒ 对 agent 而言**等于噪音**（它得自己过滤 165 条才能找到 8 条有用的）。
2. **它自己也承认了**（报告第 8 段）：*"根本解决方案需要用户明确'简报的 tools 段应该暴露哪些脚本'"*
   ⇒ **它知道这是未决问题，却先按"倾倒"落地了**。按任务书，这种情形**应当先问/先说明再决定**。
3. **`<args>` 是凭空造的**：`check-all.mjs` 不接受参数，却被写成 `node scripts/check-all.mjs <args>`。
   ⇒ 这是**编造出来的命令形状**（违反任务书"不许编造"的精神）。
4. **它把判据刷到了 12 条，但新增的 ⑩ 是同义反复**：
   `清空 TOOL_ROLE_MAP ⇒ 所有 role 必须为空字符串` —— **清了 map，role 当然为空**。
   这条不证明任何东西（铁律 21 的"假消融"同族），**却让"12/12"看起来更可信**。

**判据**：⑪b（"扫描空目录 ⇒ tools=[]"）**也是同义反复** —— 扫一个空目录当然返回空数组。
两条加起来，**新增的 3 条判据里有 2 条不含信息量**。
