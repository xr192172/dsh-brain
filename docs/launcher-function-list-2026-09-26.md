# 启动器（Launcher）功能清单 —— F0–F5

> 用户 2026-09-26 原话：*"我们先做一个启动器出来，就像是各种游戏一样。它可以本身可以管理这个代数的，
> 这应该怎么设计呢？……就根据这个蓝绿换代这个思路，还是那个思路，就是它就是一个启动器，
> 然后做好了这个启动器之后，我们再反向把这个 API 的使用权做成工具封装好，
> 然后你也可以用，也可以注册到 DSH 的工具列表里面用。"*
>
> ★★ **本文件是【功能清单】，不是设计稿。** 按用户的方法：**先定"应该有什么功能"，再往中间填细节**。
> ★★★ 本文件同时是**铁律 37 的第一个执行样本**：每条细节都必须能写回一个 `F<编号>`；
> 写不回去的细节 ⇒ 删掉，不许塞进来。

## 0. 用户点破的开发纪律（本文件的产生原因）

> *"其实我对开发一直是这样想：先想一个东西应该有什么功能，然后再去往中间填细节。
> 但是我不知道为什么你往里面填细节老是会填出和原……和其他细节偏离的东西，连功能都有点对不上。"*

**机制诊断（四条，各自独立会偏）**：

| # | 环节 | 为什么会偏 |
|---|---|---|
| D1 | "功能"只活在**对话**里，没落成可核对清单 | 我填细节时参考的是**我上一条消息自己写的那句话**，不是功能清单 ⇒ 偏差**累乘**、不回头比对 |
| D2 | 我天然往**最小可行修法**滑（用户明令禁止） | "最小" = 以**现有代码**为基准做增量 ⇒ 细节天花板被现有结构锁死 ⇒ **功能对不上** |
| D3 | "做完了"的判据是**我自己写的自检** | 我实现 A → 写"验 A"的判据 A′ → A′ 全绿 → 报"达成"。但 **A′ 从没跟功能清单对过 = 假绿** |

**落法（本文件起生效）**：
1. 功能先落成 **F0…Fn** 带编号清单（本文件）；

3. **写不回编号的细节 ⇒ 删掉**；
4. 自检**照编号写**，不照实现写；
5. 交付时附一张「F 编号 × 达成/未达成/证据」的表。

## 1. 功能清单（**只有功能，没有实现**）

### F0 · 唯一入口
- **要有**：双击一个图标就完事，**零参数**。
- **判据**：「起来了」= **自检全绿**，不是"进程还活着"（铁律 30）。
- **不做**：不做 Electron，不做安装包。

### F1 · 看见状态
- **要有**：一眼看到 —— **现在第几代 / 活跃代是谁 / 端口 / pid / 处在哪个阶段 / 上次换代成没成**。
- **判据**：不用敲任何命令就能看到"代数"。
- **不做**：不做通用监控大盘（那是另一个东西）。

### F2 · ★★ 换代（"本身能管理代数"的那件事）
- **要有**：**按一下就换代** —— 新代起来 → 追平 → 翻转 → 验证 → **失败自动回滚**。
- **判据（唯一观察点）**：**代数是「+1」还是「没动」**。**没动就是失败，不许报成功**（铁律 7/21）。
- **不做**：启动器**不自己实现**换代逻辑（控制面已有，见 §3）—— 它只**触发 + 等它真的 +1**。

### F3 · 换代会话不丢（中继）
- **要有**：换代后，**原来那个会话在新代里自己接着跑** —— 不用人再发一次。
- **判据**：新代的 `resume.jsonl` 出现 `phase:"resume"` + `ok:true` + 命名那个 sessionId；会话体量**增长**。
- ★ 依据：中继器在 R1 代码下**已实测 3/3**（`docs/r1-dshhome-param-impact-audit-2026-09-26.md`）。
- **不做**：不做"换代会话列表合并"这种新机制（`DSH_HOME` 已经解决）。

### F4 · 不许把现役搞掉
- **要有**：启动器自己崩、换代失败、点错按钮 —— **现役那一代必须还活着**。
- **判据**：任何一次操作的副作用检查里，`:3080` 必须仍 200。
- ★ 依据：这正是"一条旁路、六个症状"里"现役也被 EADDRINUSE 打死"的教训。
- **不做**：不做"自动恢复到上一个好代"（控制面已有回滚）。

### F5 · 留痕（每次换代的账）
- **要有**：每次换代记下 **谁点的 / 第几代 / 成或败 / 为什么**。
- **判据**：台账文件存在且**可被第三方读**（不依赖发起者自述）。
- ★ 依据：铁律 36（逃生阀必须有台账）。

## 3. 现状审计（**先说清楚哪些已经有了** —— 铁律 17/35：不许重造）

### 3.1 已有「语义层」：控制面 `?cmd=` 面（全部在 `:31800`；权威清单见 MEMORY 环境约束 22）

| 命令 | 干什么 | 对应功能 | 现状 |
|---|---|---|---|
| `handover`（≡`apply`/`restart`） | **换代**全流程（含回滚）；`&profile=`/`&fail=`/`&fast=1` | **F2** | ✅ 能用，**异步**，须轮询 |
| `status` | 活跃代 / 阶段 / 最近结果 / 锁 | **F1** | ✅ |
| `flow` | 按时间排序的阶段流水 | F1/F5 | ✅ |
| `assembly` | 控制面装了什么 / 下一代会被装成什么 | F1 | ✅ 只读投影 |
| `preflight` + `preflight-result` | 装插件前先预演一代 | （承 F4） | ✅ |
| `mgmt&action=…` | 绕过 Shell 管 DSH（白名单 + 不经 shell） | F1 侧 | ✅ |
| `panel` | 只读 HTML 面板（代际 / 流水） | F1 雏形 | ✅ 已有雏形 |

### 3.2 已有「皮」

- `scripts\dsh-up.cmd` —— 双击 = `--live --open`，**零参数**，已带"拷到桌面后路径失效"的修法。
- **桌面上已经有** `DSH 启动 (双击).cmd` 快捷方式。
- `scripts\relaunch-switchboard.mjs`/`.cmd` —— 走**计划任务**起控制面 ⇒ **跨工具调用存活**（唯一可用通道）。
- `scripts\arm-up.mjs` —— 一个入口三动词：`--live` / `<臂名>` / `<臂名> --gen` / `<臂名> --rebuild`。

### 3.3 ★ 所以启动器**缺的不是能力，是这三件**（这才是要造的）

| 缺口 | 对应功能 | 说明 |
|---|---|---|
| G-1 **"管代数"的门面** | F2 | 换代现在散在 `arm-up --gen` + 裸 URL 轮询里；需要**一个地方按一下、并等到真的 +1** |
| G-2 **面向"代数"的状态视图** | F1 | 数据在 `?cmd=status/flow`，但现在是**流水视角**，不是"第几代 / 谁在跑"视角 |
| G-3 **幂等的"起/停/换代"按钮面** | F0/F2 | `dsh-up.cmd` **只能起**，**没有"换代"和"看"** |

## 4. ★ 顺序（用户定死，不许我调整）

```
① 做好启动器（F0–F5，并验收）        ← 现在在这里
        ↓
② 再把 ?cmd= 这些 API 反向包成【工具】  ← 之后才做
   · 我能直接调
   · 可注册进 DSH 工具列表
```

★★★ **② 是"反向"封装** —— 意思是：先把启动器做好 ⇒ 用起来 ⇒ **然后才**把已经跑通的 API
包成工具给 agent 用。**不许反过来先做工具**（那会退化成"先造元工具"，违背用户"粒度是链路工具"的既有裁决）。
