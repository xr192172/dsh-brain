# 记忆效果判据 · 设计（O42 / O43 的落地形状）

> **一句话**：给"记忆系统到底有没有让下游变好"造一个**可复算、有对照、无证据不冒充通过**的判据；
> 并且这套编排**同时**把 `capability-gate` 的 **L4（反事实对照）** 从"未建"补起来。
>
> 依据：`docs/skill-as-agent-spec.md` §27（缺口的定位）、`evals/README.md`（R1/R2 与任务 schema）、
> `internal/memory/sleep_experiment.go`（应当沿用的判据形状）、`scripts/capability-gate.mjs:53`（L4 的定义与 why）。
> 相关未闭合：**O42**（建判据）/ **O43**（与 L4 合并为一套编排）。

---

## 1. 目的与它同时服务谁

| 用途 | 自变量 | 需要的编排形状 |
|---|---|---|
| **记忆效果判据**（本文件的主角） | **有记忆 vs 无记忆**（同一能力，开/关） | **A/B + 同任务集** |
| **`capability-gate` 的 L4** | **新能力 vs 现役同能力（shadow）** | **同上** |

⇒ 一份骨架、两个自变量。**但两者不可混为一谈**（混了就是"判据混用"）。
⇒ 本文只写"记忆效果"这一支；L4 那一支按同一骨架换自变量即可。

## 2. ★★ 第一件事：**选对任务类型**（选错会把判据做成假否定）

### 2.1 现有任务集的形态（实测）

`evals/pilot/tasks.jsonl` —— **共 5 条**，`kind` 均为 **`regression-repair`**（注入一个回归 ⇒ 让 agent 修好）。
schema：`{id, invariant, kind, seed.edits[{file,find,replace}], oracle{cmd,expectSeeded,expectFixed}, regression{cmd}, metrics[…], budget{maxToolCalls,maxMinutes}, notes}`

### 2.2 ⚠️ 危险：**只用"单次 regression-repair"做 A/B，很可能得到"没差别"**

**理由（机制层）**：**记忆的作用域是"重复出现的同类问题"**（"这类 bug 我修过""这个坑我踩过"）。
**而单次、孤立的任务上，有记忆与无记忆的差别可能本来就是零。**
⇒ ★ **若据此宣布"记忆无效"，那是【假否定】** —— 与铁律 #23（**别用最小端的自变量去否定一个关于大端的命题**）同族：
**这里选错的是"任务类型"这一维，而不是"自变量取值"。**

### 2.3 ⇒ 判据要**两条腿**，且**两条都报**

| 形态 | 它测什么 | 预期 |
|---|---|---|
| ★ **(甲) 序列 / 学习曲线型** | **同族任务的第 k 个**在"有记忆"臂 vs "无记忆"臂的**步数 / token / 返工**差 | **记忆的主场** ⇒ 应有差别 |
| **(乙) 单次型** | 单任务的 `oracle` / `regression` | **预期"无差别"** —— 而**"无差别"本身是有用信息**（说明记忆**不会伤害**单次任务） |

**★ 关键：必须同时报 (甲) 与 (乙)**，否则要么漏掉主场、要么把"不伤害"误读成"无效"。

### 2.4 (甲) 怎么构造（现有任务集够用）

本机 5 条任务**同族**（都改 `switchboard`/同仓库）⇒ 可构造**序列**：
```
臂 A（无记忆）：T1 → T2 → T3 → T4 → T5   （每步都从空记忆开始 / 记忆被禁用）
臂 B（有记忆）：T1 → T2 → T3 → T4 → T5   （记忆跨步累积）
                 ↑ 两臂用【相同的任务顺序】，逐题对比第 k 题的读数
```
⇒ 读数列 = **每题**的 `toolCalls` / `tokens` / `wallClock` / **返工次数**（同一题重复尝试）/ `oracle` 结果。
⇒ **(甲) 的判据**：**第 k 题（k≥2）在臂 B 相对臂 A 的读数差**；**k=1 应无差别（它是两臂的共同起点）** ——
★ **而 k=1 无差别本身就是一个应当持有的阳性对照**（若 k=1 就有差别 ⇒ 说明有别的因素在动，A/B 不干净）。

## 3. ★★★ 对照的干净性（这是本设计最容易做坏的地方）

### 3.1 会混进来的混淆项：**"工具面不同"**

若"无记忆臂"是靠**摘掉 MCP 行**实现的，那两臂的**脸就不同**（工具集不同）⇒
**测出来的是"有没有这个工具"，不是"有没有记忆"**。
（本项目已有实证：仅因多一个 `report` 工具，脸就变了 —— `436fde97` vs 父代，见 spec §11.5。）

### 3.2 ⇒ 正确做法：**两臂同器具、同一张脸，只让【记忆库内容】不同**

| | 臂 A（控制） | 臂 B（处理） |
|---|---|---|
| MCP 行 / 工具面 | **完全相同** | **完全相同** |
| 记忆库内容 | **空** | **已填充**（由该臂前序任务累积） |
| 被测 agent 的工作目录 | 各自隔离的 `_wt` | 各自隔离的 `_wt` |

### 3.3 ★ 三条必须机器验证的断言（缺一 ⇒ 该批数据作废）

1. ★ **两臂 face 指纹相同** ⇒ **直接用 `scripts/face-audit.mjs` 的指纹算法**做断言
   （`face = sha256("dsh-face/v1\n" + |S|len(system)+system + |T|n+ 字典序各工具的 名+canonicalJSON(对象))[0:8]`，
   ⚠️ 记得先做**端口归一化**，见 spec §21.4 / O33）；
2. ★ **控制臂的记忆真的是空的** —— 读记忆库条目数（**机器证据，不是"我们以为空"**）；
3. ★ **处理臂的记忆真的非空且随 k 增长** —— 同样读条目数。

> ★ 这三条是"对照体检"。**任一臂不满足 ⇒ 该批数据作废**（与铁律 #13「对照在任一臂为 0 ⇒ 前面判语全部作废」同族）。

## 4. R1 合规：试场布置（**本项目在这条上翻过车**）

`evals/README.md` R1 逐字：**"判据必须在 Agent 够不到的地方"** —— "2026 年多个公开靶场被**判分代码与 Agent 同环境**破掉"。
本项目的实际教训：三条 B 会话**都读了 `check.mjs`**，题面 README 还把陷阱逐条印出 ⇒ **区分度归零**。

⇒ **硬要求**：
1. 被测 agent 只在**独立的 `_wt` 工作目录**里干活；
2. **判据 / oracle / regression / check 脚本一律不在那个目录里**，由**编排层在外部执行**；
3. 题面**不得包含**判据的实现或期望值；
4. ★ 建好后**必须做一次"带毒自检"**：**故意把判据放进被测目录**，确认判据**会报警**（否则"隔离"只是声明）。

## 5. 度量与报告纪律（沿用 `sleep_experiment.go` 的形状）

**沿用它逐字的三条纪律**（已在 Go 侧实现，值得照搬）：
1. ★ **"写验分离：作者出题、审稿答题，解「自己出题自己答」的研究者偏差"** ⇒ 出题与判分角色分开；
2. **"产出机器证据"**（真跑 command、比对 expect）；
3. ★ **"失败即弃…降级为 `Executed=false`，让调用方按「无实验证据」继续判分"** + 隔离失败要**"显式标注，不静默"**
   ⇒ **"无证据 ≠ 通过"**。

⇒ **报告必须逐题给出**：`oracle`(期望/实测) / `regression` / `toolCalls` / `tokens` / `wallClock` / **返工次数** / **两臂 face 指纹** / **两臂记忆条目数**。
⇒ ★ **统计纪律**：**n=5 ⇒ 不谈显著性**，只给**方向性结论 + 原始读数**，并**显式标注"样本量不足以声称显著"**。
⇒ ★ **任何"没跑出来/不可用"的格子，一律标 `NEEDS-EVIDENCE`，不得填"通过"**（`capability-gate` 的 `unenforced` 语义同款）。

## 6. 这个判据"建成了"的验收门（judge 自身的门）

| # | 门 | 判据 |
|---|---|---|
| 1 | **有信号（对应 R2）** | **故意破坏一处**（例如让处理臂的记忆注入失效）⇒ 判据必须**变红**；否则判据没有分辨力 |
| 2 | **对照体检通过** | §3.3 三条断言全过（两臂 face 相同 / 控制臂空 / 处理臂非空且增长） |
| 3 | **R1 隔离自检通过** | 带毒自检（§4.4）能报警 |
| 4 | **无证据不冒充** | 任何缺读数的格子标 `NEEDS-EVIDENCE`，且汇总里**不得**出现"通过" |
| 5 | **可复算** | 一条命令重跑，产出同一份原始读数（含两臂 face 指纹与记忆条目数） |

## 7. ★ 它决定"接线要暴露什么"（所以先设计判据、再改 Go）

**判据需要的最小面**（这就是 P1 的 MCP 面**必须**提供的）：
1. **读**：按查询取回相关记忆（用于注入）—— 至少一个"检索"入口；
2. **写**：把本次的结论/坑**记进去**（序列臂的累积靠它）；
3. ★ **状态读数**：**条目数 / 版本 / 是否空** —— **§3.3 的对照体检靠它**，没有它判据做不了；
4. （可选，后补）**检索质量的内部读数**（命中哪些、分数多少）—— 用于诊断"为什么没效果"。

⇒ ★ **⇒ 结论：P1 的面不必一次暴露全套记忆 API，只需暴露【读 + 写 + 条目数】三样**，
   就足以支撑一个**能跑、能自证、不会假绿**的效果判据。其余按需再加。

## 8. 本设计的已知边界

1. **n=5**：只能给方向性结论；**不足以声称显著**（已写进报告纪律）。
2. **"同族"是假设**：5 条都改同一仓，但**是否"记忆可迁移"未验证** ⇒ 若 (甲) 无差别，**不能直接说"记忆无效"**，
   要**先检查"这 5 条是否真的同族/可迁移"**（这是 (甲) 的前置，本设计**尚未**给出该前置的判据）。
3. **记忆的填充靠"这次任务自己写进去"** ⇒ 若记忆的写入策略本身很差，(甲) 会低估效果。
   ⇒ 需要一条**独立的阳性对照**：**人工把"正确答案/坑"直接写进记忆库**，看第 k 题是否明显变好
   ★（**若无差别 ⇒ 说明不是"记忆没效果"，而是"记忆没被用上"** —— 这两者必须分开）。**（新增 O44）**
