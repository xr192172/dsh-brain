# 训练场 = 题库（agent-agnostic）？ + 蓝绿换代能不能当启动器？—— 2026-09-25 用户提问的结论

> 用户原话：
> *"既然是训练场。那么训练场不应该做成那个**一键刷新题目**，然后**选择题目进入题库**，
> 然后**与 Agent 无关**，Agent 进去只需要**做题**这种吗？"*
> *"关于 B 的这个问题，我们如果把它就是**蓝绿面板当做是启动器**来看的话，那么只不过是
> **当前的这个 agent 启动了下一代的 agent**，然后让下一代并且指挥下一代的 agent
> **派出某一个需要测试的部分进入这个实验场**，然后进行实验，然后**记录成绩**，
> 这个概念是不是比我们现在的**更流畅而且更容易实现**？"*

---

## Q1：训练场 = 题库（与 Agent 无关）—— ★★ **同意，而且它指出了我们现存的一个耦合**

### 为什么同意
"训练场"的本体应该是**题**（题目 + 题目的生命周期），**不是**跑题的机器。而我们现在**没有题**：
- 所谓的"题"是**我每次临时手写的 task book**（`out/_tasks/t1-guard.md` 等）
  —— **没有题库、没有版本、没有难度/前置/判据字段、不能复用、无法比较**
- ⇒ 直接后果：**每来一件事都要我从头写一份**，而且**两份任务书的验收标准不一样**（无法横向比成绩）

### ★★ 但要点出一个**现存的耦合**（这是我们真正的债）
**现在的实现里「训练场 = 臂」是耦合的**：
- `isolated-instance` 生成的实例**带着臂身份**（`DSH_ARM_SELF` / `DSH_ARM_DENY`）与**臂间隔离层**
- 也就是说：**"场"这个字里混进了"谁在场/谁不能碰谁"**

⇒ 用户说的"**与 Agent 无关**"恰好命中这点。正解是把两层**拆开**：

| 层 | 管什么 | 该不该认识 agent |
|---|---|---|
| **训练场 / 题库** | 题（来源/版本/难度/判据/成绩） | ★ **不认识**。它是"试卷 + 题库" |
| **实验（一次 run）** | **谁来做、以什么身份、允不允许碰别的臂** | ★ **认识**：身份与隔离**属于实验**，不属于场 |

⇒ **迁移动作**：把 `DSH_ARM_SELF` / `DSH_ARM_DENY` / `arm-isolation` 的语义
   从"场的属性"改成"**实验的属性**"（一次实验带一个身份；场本身无身份）。

---

## Q2：蓝绿换代当启动器？—— **拆成两半：一半不行，一半是对的而且更容易**

### ✅ **对（而且比我说得更简单）——★ 本节已按用户 2026-09-25 的纠正重写过**
> 用户纠正（逐字）：*"蓝绿换代……它只是把当前代映射在了 3080 端口，后面是不同的端口。
>  也就是说它**完全可以当前端口去操作下一代的端口**……你就是**另起**，等于这个 agent **另起了另一个 agent** 仅此而已，很简单。"*

**我上一轮说"换代换不了隔离"是错的** —— 我漏了最关键的一点：
**换代就是 `spawn` 一个新进程**，而 **`DSH_HOME` 是进程的环境变量**。
⇒ 给新代一个**不同的 `DSH_HOME`** + **一段自己的端口** ⇒ **就是一个独立实例**；
   而 `3080` 只是**"前门指向谁"**（`front door :3080 -> gen A :3082`）⇒ **不 flip = 另起一个 agent、但不当现役**。

⇒ ★★ **"另起一个 agent" 不需要任何新机制** —— 它**就是**「**另起一代 + 不 flip**」。
⇒ ★ 而且**我们早就有这个原语**：**`arm-up <臂名>`** 干的正是
   「另起一代 + 自己的 `DSH_HOME` + 自己的端口段 + **不映射到 3080**」——
   之前只是**没把它认成这个东西**（错当成"训练场专用脚本"）。

⇒ 所以 Q2 的结论是：**不是"蓝绿当启动器 ✗"，而是"蓝绿里的『spawn + 端口 + 可选 flip』这一半，本来就是起 agent 实例的原语"** ✓
   并且**由当前代发起**（把"起一代 / 发题 / 收卷 / 记分"交给 DSH 侧调用）**确实比现在更流畅、也更容易** —— 因为零件全都有。
