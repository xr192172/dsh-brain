# 训练场 = 题库（agent-agnostic）？ + 蓝绿换代能不能当启动器？—— 2026-09-25 用户提问的结论

> 用户原话：
> *"既然是训练场。那么训练场不应该做成那个**一键刷新题目**，然后**选择题目进入题库**，
> 然后**与 Agent 无关**，Agent 进去只需要**做题**这种吗？"*
> *"关于 B 的这个问题，我们如果把它就是**蓝绿面板当做是启动器**来看的话，那么只不过是
> **当前的这个 agent 启动了下一代的 agent**，然后让下一代并且指挥下一代的 agent
> **派出某一个需要测试的部分进入这个实验场**，然后进行实验，然后**记录成绩**，
> 这个概念是不是比我们现在的**更流畅而且更容易实现**？"*

---

## Q1：训练场 = 题库（与 Agent 无关）—— ★★ **同意，而且它指出了我们现存的一个耦合**

### 为什么同意
"训练场"的本体应该是**题**（题目 + 题目的生命周期），**不是**跑题的机器。而我们现在**没有题**：
- 所谓的"题"是**我每次临时手写的 task book**（`out/_tasks/t1-guard.md` 等）
  —— **没有题库、没有版本、没有难度/前置/判据字段、不能复用、无法比较**
- ⇒ 直接后果：**每来一件事都要我从头写一份**，而且**两份任务书的验收标准不一样**（无法横向比成绩）

### ★★ 但要点出一个**现存的耦合**（这是我们真正的债）
**现在的实现里「训练场 = 臂」是耦合的**：
- `isolated-instance` 生成的实例**带着臂身份**（`DSH_ARM_SELF` / `DSH_ARM_DENY`）与**臂间隔离层**
- 也就是说：**"场"这个字里混进了"谁在场/谁不能碰谁"**

⇒ 用户说的"**与 Agent 无关**"恰好命中这点。正解是把两层**拆开**：

| 层 | 管什么 | 该不该认识 agent |
|---|---|---|
| **训练场 / 题库** | 题（来源/版本/难度/判据/成绩） | ★ **不认识**。它是"试卷 + 题库" |
| **实验（一次 run）** | **谁来做、以什么身份、允不允许碰别的臂** | ★ **认识**：身份与隔离**属于实验**，不属于场 |

⇒ **迁移动作**：把 `DSH_ARM_SELF` / `DSH_ARM_DENY` / `arm-isolation` 的语义
   从"场的属性"改成"**实验的属性**"（一次实验带一个身份；场本身无身份）。

## Q2：蓝绿换代当启动器？—— **拆成两半：一半不行，一半是对的而且更容易**

### ❌ 不行的一半：**换代 ≠ 起实验场**
蓝绿换代（`?cmd=handover`）换的是**同一个实例内的下一代进程/插件树**：
- **同一个 `DSH_HOME`**、**同一段端口**、**同一份数据**（会话、能力库、`storages/` 全是同一份）
- ⇒ 它是**部署语义**（"把新代码换上去、旧的回滚"），**不是隔离语义**（"另开一个干净的世界"）

而**实验场必须数据隔离**（否则实验会**改到主世界的数据**，成绩也就不干净了）。
⇒ **拿换代当启动器，会把"部署"和"隔离"两件事混成一件** —— 这正是今天已经踩过的那种坑
（同一个 `:3101` 池端口、同一份日志，就是"两个世界共用一件东西"的教训）。

### ✅ 对的一半：**由"当前代"启动并指挥下一代去跑实验** —— 而且**更容易实现**
用户这句话的**真价值**不在"蓝绿"，而在**发起者是谁**：
> 现在的发起者是我（**外部脚本**：`arm-up` + `dsh-delegate` 由我调用）；
> 用户要的是**当前代自己发起**（"current agent 起 next agent，并指挥它派测试对象进场"）。

⇒ ★★ 这与用户一贯的主张（"**用 DSH 当子 agent，别套外层的子 agent**"）是**同一条**，
   只是把它**架构化**了：**发起与指挥应当发生在 DSH 内部**，而不是在我的 shell 里。

**但通道不是"换代"，而是**：把"起场 / 发题 / 收卷 / 记分"做成 **DSH 侧的一个工具（或一组命令）**，
由当前代调用它 ⇒ 它去**起一个隔离实例**（那才是"实验场"）⇒ 派题 ⇒ 收卷 ⇒ 记分。

⇒ **一句话**：**"蓝绿面板当启动器" ✗；"当前代启动并指挥一个实验" ✅** ——
   而且后者**确实比现在更流畅**（少一层人工中转），也**更容易实现**（我们已经有全部零件：
   `arm-up` 起场、`task-bank` 发题、`tool-pool` 记分 —— 只差把它们的**调用者**从 shell 搬进 DSH）。

## 最小落地（分三步，每步都有可判定判据）

| # | 动作 | 判据（可判定） |
|---|---|---|
| 1 | **建题库** `evals/tasks/`：把"题"变成**数据**（id/来源/难度/任务书正文/判据/历史成绩） | `task-bank.mjs list` 能列出；**输出里不得出现 arm/agent 字段**（★ 证明"与 agent 无关"） |
| 2 | **把已有的 3 份真题入库**（T1/T2/T3 任务书 + 它们**实测的成绩**） | `task-bank.mjs show <id>` 含正文与成绩；成绩逐字来自实际运行记录 |
| 3 | **把发起者搬进 DSH**（当前代 → 起场 → 发题 → 收卷 → 记分） | 一次"由 DSH 发起"的实验全程留痕（谁发起、哪题、哪场、成绩） |

★ 本文件只固定**结论与边界**；第 1、2 步**当场做**（见 `scripts/task-bank.mjs`），第 3 步留下清单。
