## 一、先回答"能不能用它们测 Agent"：能，而且**这正是 2026 年的主流做法**

你自己的直觉是对的，而且在 2026 年被明确地制度化了：

- 公开靶场现在普遍给**两套榜**：**bare model**（剥掉脚手架，测模型本体）与 **scaffolded**（带上完整工具栈，测 Agent）。
  同一批 GAIA 任务，两个榜差 **30–50 个点**（Princeton HAL 的观测）。
- 2026 年出现了专门测"脚手架效应"的 **Harness-Bench**，其立论就是：绝大多数 Agent 榜把**模型和脚手架混在一起报**，
  报出来的和其实不是模型的能力。
- 一句话结论：**在固定模型的前提下换脚手架/提示/工具集，收益往往比换模型更大** ——
  HAL 的原话是"framework value frequently dwarfs model differences"。
  ⇒ 我们做的正是这件事（固定模型，改 @dsh-brain 那一层），所以这些榜**对我们的用法是"减去模型变量之后的差分"**。

## 二、靶场清单（按"测什么"分类）

| 靶场 | 场景 | 测什么 | 判分方式 | 数据形态 | 我们能用吗 |
|---|---|---|---|---|---|
| **SWE-bench Verified**（500 题，Docker/Conda） | Python 仓库真实 issue 修复 | 代码编辑 | **仓库单测**：`FAIL_TO_PASS` + `PASS_TO_PASS` 两组测试红转绿 | `repo + base_commit + problem_statement` → 期望是测试结果 | ⚠️ **只当"不许退化"的地板**，见 §四 |
| **SWE-bench Pro**（731 题） | 同上，抗污染版本 | 同上 | 同上 | 同上 | 顶模型分数从 ~88% 掉到 ~23% ⇒ 说明 Verified 被污染抬高了 |
| **Terminal-Bench 2.0**（89 题，Ubuntu Docker） | 真实终端工作流（运维/ML/安全/科学/游戏） | 端到端终端任务 | **自动测试脚本**，pass@1 | 容器镜像 + 自然语言任务 + 验证脚本 | ✅ **最贴合我们**（我们的 Agent 主要就是 shell+文件） |
| **OSWorld**（369 题，VM+截图） | 桌面 GUI 操作 | GUI 控制 | **环境最终状态**检查（文件 diff / 注册表 / 网络调用） | VM + 任务 + 后置条件断言 | ❌ 我们是纯终端/无 GUI |
| **τ²-bench**（Sierra） | 客服业务流程（航空/零售/电信） | 多轮对话 + **规则遵循** | **用户模拟器 + 共享数据库状态**；`pass^k` 重复 k 次 | 政策文本 + 工具 + 双控（用户也是 agent） | ✅ **规则遵循**这一维很值得借：我们也有 ask_user_question 与权限预设 |
| **MCP-Atlas**（Scale AI，1,000 题 / **36 个真实 MCP server**） | 工具使用 | 工具选择与调用 | **claims-based rubric**（按"必须满足的断言"打分，不用脆的精确匹配） | MCP server + 任务 + 断言清单 | ✅✅ **我们有 ~70 个 design-canvas MCP 工具**，形态完全一致 |
| **BFCL / API-Bank** | 函数调用 | 参数/顺序/结果处理 | JSON 精确匹配或执行结果 | 函数 schema + 调用序列 | ✅ 便宜、可自动化（我们的工具面很大） |
| **WebArena / GAIA / BrowseComp** | 网页/搜索/多模态 | 浏览与检索 | 环境状态 / 答案准确率 | 真实站点或问答 | ⚠️ 与我们关系弱，且**污染最重**（见 §四） |
| **GDPval** | 经济价值 | 输出"值不值专业人士的价" | 人类专家 Elo 排名 | 开放式交付物 | ⚠️ 参考其"人工 Elo"思路，成本高 |
| **Agent-SafetyBench / ClawsBench** | 安全 | 有害/越权动作 | **unsafe-action rate** 与成功率并列 | 模拟 Gmail/Slack/Drive 等 | ✅ 值得照抄：**"做完"和"做得安全"是两个指标** |

## 三、他们到底怎么测（三个机械件）

1. **harness（脚手架）**：把模型文本变成动作的那层。SWE-bench Verified 故意做得极简（容器 + 仅 bash），
   好让分数反映模型；而**脚手架、上下文管理、重试策略、工具调用预算能摆动 10–20 个点**。
2. **scoring rubric（判分）**：老榜是二元/精确匹配；MCP-Atlas 改成**claims 断言清单**（更抗格式抖动）。
   注意规则会变：MCP-Atlas 在 2026-04 把"20 轮上限"换成"100 次工具调用预算"并**重算了所有模型**。
3. **environment（环境）**：容器/VM 隔离、可重置；τ²-bench 更进一步是**双控**——
   模拟用户自己也持工具、改共享状态，所以对话**真的改变世界状态**。

**数据从哪来**：真实工单/issue（SWE-bench、Terminal-Bench）+ 人工构造的后置条件（OSWorld）+ 政策文本（τ²-bench）
+ 真实 MCP server（MCP-Atlas）。**共同点：期望结果都是"可机验的最终状态"，不是"像不像人话"。**

## 四、2026 年的四个教训（比榜单本身更重要）

1. **★ 判据（oracle）才是弱点，不是任务数**：
   - OpenAI 在 **2026-02-23 停止上报 SWE-bench Verified**：审计 138 个问题任务，**>60% 有缺陷**
     （49 个定义过窄、26 个要求了未文档化的行为）；另有审计称最难的 Verified 题里 **59.4% 的测试集根本抓不到目标 bug**。
   - ⇒ 与我们项目里的"**假绿**"是同一条教训：**门自己坏了，比没有门更糟**（它让人以为查过了）。
2. **★ 评测必须与 Agent 隔离**：多篇 2026 汇总指出，当**判分代码与 Agent 代码在同一环境**时，
   Agent 可以"一行代码改掉自己的成绩"（SWE-bench/Terminal-Bench/OSWorld 都被这样破过）；
   答案文件放在环境里（WebArena/GAIA）更是直接查表。
   ⇒ **判据要在被判定者够不到的地方** —— 这正是我们无环原则的工程版。
3. **★ pass@1 会骗人，要 pass^k（可靠性）**：2026-03 一项 23,392 次运行的研究发现，
   任务越长"能力"与"可靠性"越发散（软件工程 Graceful Degradation 从 0.90 掉到 0.44），
   而且**更强的模型崩得更频繁**（最高 19%）。我们的"换代"恰恰会拉长任务 ⇒ 必须测重复多次的稳定性。
4. **★ 成功 ≠ 安全**：ClawsBench（2026-04，6 模型 44 任务）里成功率 39–64%，而 **unsafe-action rate 达 7–33%**，
   且两者**没有一致序**。⇒ 我们的实验报告里"完成任务"旁边必须并列"越权/危险动作"。

## 五、我们该怎么用（结论）

**两层，别混：**

| 层 | 用什么 | 判什么 | 频率 |
|---|---|---|---|
| **地板（不许退化）** | 挑 1–2 个公开靶场的**小子集**（首选 Terminal-Bench 风格的容器任务；SWE-bench 只用抗污染子集） | 结构/契约/通用能力**不许变差** | 换代前 |
| **判据（是否变好）** | **我们自己的冻结任务集**（见 `evals/`）——题目来自我们真实修过的回归，oracle 用**我们已有的门** | 与现行**成对比较**的 delta（成功率 / 工具调用数 / token / 延迟 / 危险动作） | 每次换代 |

**为什么判据必须是自有的**：① 通用榜对我们**几乎饱和**（我们的活儿是特定仓库 + 特定 MCP 工具集）；
② 通用榜**抗污染性存疑**（我们自己写的题天然不可污染）；③ **我们从第一天就有现成的 oracle** ——
`scripts/test-handover-drain.mjs`（36 项）、`test-injected-message-shape.mjs`（9 项）这些门
**就是** SWE-bench 意义上的 `FAIL_TO_PASS`：把被修好的代码**反向打回去**（seed），门变红；
Agent 修好，门变绿。**任务集不用另造，把我们的回归历史反过来用就是。**

**具体到第一步（M1-step-1，本轮已开工）**：
- `evals/README.md` = 任务集格式与设计规则（含上面四条教训的落点）；
- `evals/pilot/tasks.jsonl` = 首批任务（seed = 一行反向改动，oracle = 现有门）；
- `scripts/eval-validate.mjs` = **任务有效性校验**：给每个任务打上 seed，
  必须让它的 oracle **由绿转红**（否则这题**没有信号**，是假题）——**这一步不需要 Agent、今天就能跑**。
