## §3 ★★★ 判别：什么能剪、什么不能剪

**"只留设计文档和有效实现"这个目标本身要修正一处** —— 因为在本项目里，
**诊断/核验报告不是"枝节"，它是【判据的载体】**：

- 铁律 7/11/21 都建立在"**能数出判据为真的次数**"上 ⇒ 证据必须留。
- 今天我能回答您"中继器 3/3"，靠的正是 `docs/arm-a-zombie-lease-causal-chain-*.md`
  里那套"三份证据交叉"的方法论 + 台账。
- **删掉报告 = 删掉"为什么这条判据可信"** ⇒ 下一代会把已证否的路径**再走一遍**
  （这正是我 §1 犯的错的放大器）。

**⇒ 判别表：**

| 类别 | 处置 | 判据 |
|---|---|---|
| ✅ **设计文档 / 规格** | **留** | 回答"应该怎样" |
| ✅ **未闭合清单 / 因果链诊断** | **留** | 回答"为什么现在这样"（是判据载体） |
| ✅ **有效实现 + 它的判据** | **留** | 有测试/oracle，且**今天还在被引用** |
| ⚠️ **一次性探针脚本** | **剪（先归档）** | 任务是"查明某个现象"，现象已入文档 ⇒ 脚本本体可走 |
| ⚠️ **已完成任务的临时产物** | **剪** | 在 `out/_tasks/` 之类，非交付 |
| ❌ **"已被替代的旧入口"** | **剪** | 有两份做同一件事，旧的那份没人调 |
| ❌ **找不到调用方的脚本** | **剪（需先证）** | ★ **必须先证明"确实没人调"**，不能靠印象 |

## §4 ★★ 方案：先建"影子账"，再剪 —— 不许凭印象删

**为什么不能直接剪**：本项目铁律里有一条血的教训（`_arms/a.bak-*` 的残留、
`evals/arms.json` 里"数字为真但挡的是过期参与者"）——
**"看起来没人用"和"确实没人用"之间隔着一次实测。**

**四步（每步都有判据）：**

### 步骤 1 —— 建**引用图**（只读，不改任何东西）
- 对 `scripts/` 220 个文件：解析每个文件的 `import` / `require` / `spawn*(…path…)` 路径字面量
  ⇒ 建**有向图** + **入度表**。
- 判据：**入度为 0 的脚本清单**（这才叫"候选"，不叫"可删"）。
- ★ 必须同时扫**非代码引用**：`docs/`、`.workbuddy/`、`evals/`、`scripts/*.cmd`、`package.json` 的 scripts。
  （本项目的真实坑：一个脚本可能**只被文档里的一句话引用**，但删了它，文档就成了假话。）

### 步骤 2 —— 对照"已闭合任务"清单
- 从 `docs/` 与日更里抽出"已查明/已修"的现象 ⇒ 它对应的探针脚本进**归档候选**。
- 判据：**该现象已有文档记录** ∧ **该脚本入度为 0** ⇒ 才进候选。

### 步骤 3 —— 归档而不是删除（**关键**）
- `scripts/_archive/YYYY-MM-DD/` + 一份 `ARCHIVE.md` 说明"为什么它可以走、将来怎么找回来"。
- ★ **理由**：本项目铁律 19/21 要求"复现"；**删掉脚本 = 毁掉复现能力**。
  归档 = 从"迷路区"移出，但**复现路径不丢**。

### 步骤 4 —— 剪完**证明没剪坏**
- 跑现存全部门：`check:profile` / `check:bom` / `test-mgmt-surface` / `arm-up --selftest` / `task-bank --selftest` …
- ★ 判据：**基线红不变多**（既存红是 3 条，见 MEMORY.md"未闭合"）⇒ 任何**新增红**都说明剪错了。

## §5 ★ 但更重要的一件事：**先做 R1，再瘦身**（顺序不能反）

**理由（这是本次复盘最有价值的推论）**：
`isolated-instance.mjs`（**902 行**）与 `arm-up.mjs` 里相当一部分代码，
**存在的唯一理由就是"`spawner.ts` 不带 `DSH_HOME`"**。

⇒ 若**先瘦身**：我会按"现在这个形状"判断哪些是枝节 ⇒ **很可能把"其实就是 R1 该吸收的那部分"当枝节删掉**，
再实施 R1 时又要重写一遍。
⇒ 若**先做 R1**：`arm-up` 起代改走 `?cmd=handover` 之后，**`isolated-instance` 的准备逻辑大面积失去理由**，
届时剪枝是**照着"真正的死代码"剪**，而不是照着"我以为的枝节"剪。

**⇒ 顺序建议：**
```
① R1（spawner.ts: dshHome 显式入参 + WORK_DIR 同行）   ← 前提，影响面已盘清
② 复验（重跑一次真换代，证中继器仍 3/3）              ← 铁律 21 消融自证
③ R2（arm-up 起代改走 ?cmd=handover）                  ← 旁路正式作废
④ ★ 此时才瘦身：删旁路 + 归档死脚本 + 收 docs
⑤ 收尾：重跑全门，确认基线红没变多
```
