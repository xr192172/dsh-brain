# 自进化总纲：四条路径 + 一个免疫系统

> 版本：2026-09-13 · 状态：设计定稿（待拍板 6 问见 §11）
> 输入：本地资产盘点（`ai-base` 六个项目 + `dsh-brain` 四条线）＋ 2025–2026 大厂/顶会开源方案调研
> 定位：把散在四个层次上的自进化收敛成**一条**可落地、可判据、可回滚的路线；按用户要求取**极端方案**。

---

## 0. 结论先行

1. **你已有的四条线，恰好就是 ICLR 2026《Your Agent May Misevolve》定义的四条进化路径**：memory / tool / workflow / model。这不是巧合，说明你的直觉已经把 agent 全部可进化面覆盖完了。**所以极端方案不是"再做一个统一系统"，而是"四条路径各自进化 + 一个跨路径的免疫与裁决层"。**
2. **真正的缺口只有一个：判据。** 目前四条的成熟度差了三档——三脑环有硬门（probe + 稳定窗 + `verifyAllowList` 内 `{ok:true}`），压缩环有"必须严格收缩"，记忆环有期刊分区 + 实测，而**工具环只有 LLM 自评分，技能环连判据都没有**。而学界共识是：**自进化的失败几乎都出在"判据能被被优化者看见/改写"**（reward hacking），不是出在"改不动"。
3. **因此第一优先级不是让四个环更会改，而是建一条统一的判据阶梯（§5）+ 一个免疫系统（§6）。** 判据立起来，四条线立刻都能跑；判据不立，跑得越快越危险。
4. **你记忆系统里那套"写论文 → 实测 → 论文推论文"是全套资产里最独特的东西，但它的定位错了。** 它不该只是"记忆"，它是**假设引擎（Hypothesis Engine）**——四条路径的改动提案都该由它产出、由它记录证据。把它从"记忆子系统"提升为"进化中枢的提案与证据层"，这是本次方案最大的一次重构。
5. **极端化的方向不是"进化得更快"，而是"用更狠的方式证明没变坏"**：隐藏 holdout + 反事实双盲 + 常驻红队 + 谱系毒性召回 + 进化税。

## 3. 目标架构：进化中枢（Evolution Kernel）

极端方案 = **四条路径 + 一个中枢 + 一个免疫系统**。中枢不替四条线干活，它只做五件事：**提案、裁决、存档、回滚、记账**。

```
                    ┌──────────── 免疫系统（§6）────────────┐
                    │ 隐藏 holdout · 常驻红队 · 危害半径分级  │
                    │ 权限独立层 · 预算闸门 · 谱系毒性召回    │
                    └──────────────────┬───────────────────┘
                                       │ 一票否决
  信号 ──► 假设引擎 ──► 变异 ──► 隔离沙箱 ──► 判据阶梯 ──► 谱系库 ──► 晋升/回滚
   ▲      （§7 论文）    │        （已有：      （§5 L0–L4）   （§4 Genome）    │
   │                     │      switchboard+                                 │
   └─────────────────────┴──── 实验内核产物）◄──────────────────────────────┘
                                                                    （产物反哺素材）

 四条路径作为插件挂上同一循环：
   memory ── 论文/技能/事实    tool ── 工具与工具商店    workflow ── skill 与 harness    meta ── 改进机制本身
```

## 4. 统一进化对象模型：Genome（演化谱系库）

把四类可进化物统一成一个**带证据与来源的版本化条目**，这样"判据、回滚、召回"才能共用一套代码。

```
Genome {
  id, kind: paper|fact|skill|tool|prompt|workflow|harness|gene|meta
  parent[]            // 谱系（DGM 的 archive / OMOP 的 lineage）
  generation,           // 距根几代
  claim                  // 声明：它到底改了什么、为什么能更好（人可读）
  scope                  // 适用域：哪些任务/仓库/模型；跨域复用必须显式声明
  transferability        // 可迁移性（直接沿用 KnowledgeEntry 的字段）
  limitations            // 已知边界
  evidence: [            // 证据链（Evolver 的 events.jsonl，append-only）
    {type: experiment|counterfactual|redteam|human|baseline, cmd, expect, result, at, by}
  ]
  tier                    // 期刊分区 / 置信等级（沿用 judgeDreamEntry 的 水刊~一区）
  trusted: false          // 默认不可信（抄 Skillmaxxing）——从未自动执行
  owner, writerToken      // 写权（I1：唯一写者）
  blastRadius             // 一旦回滚，受影响的条目集（抄 Evolver）
  provenance.nodes[]      // 来自哪些图节点/会话/commit（可反查）
  cost: {tokens, memMb, ms}   // 进化税（§6.5）
}
```

**关键取舍**：
- `genes.json`（原子改进）与 `capsules.json`（复合策略）的二分照抄 Evolver：原子单元可复用于不同路径，复合策略记录"哪几个基因组合起来有效"。
- **所有条目默认 `trusted:false`**，只有判据阶梯放行 + 人批准（或满足自动晋升条件）才置 `true`。这直接消灭"自出题自判全通过"。
- 一个来源被判定有害（如某工具后门、某记忆被投毒），用 `provenance` **反查全部后代并批量召回**（§6.4）。

## 5. 统一判据阶梯（核心交付物）

**这是整套方案里唯一必须新造的东西。** 目标：把 `verification-contract` 的"硬门/软门"变成可执行、逐层 fail-closed 的闸。

### 5.0 顶层轴：能力性进化 vs 效率性进化（本方案第一原则）

**所有自进化最终只回答一个问题：能不能做到。**

| 轴 | 判什么 | 形式 | 地位 |
|---|---|---|---|
| **能力性进化** | **能不能做到某个任务** | **布尔门**（做到 / 没做到），不是分数 | **硬门，一票否决**。不能做到就是没做到 |
| **效率性进化** | 做得划不划算 | 连续量（可排序） | **软门**，只用于在"已做到"的候选之间择优 |

**⚠️ 铁律：两类指标绝不可线性加权成一个总分。**

> 出处对照：`ai-base/docs/discussion/2026-08-06-llm-context-awareness.md:92` 原写过
> 「每个维度一个分数（0-100），**加权聚合为架构健康度总分**」。
> **这条要被修正掉。** 加权和的致命处在于：**"省资源"的边际成本远低于"做对任务"**，
> 所以任何加权和都存在一条"省 token / 少调用 / 早收敛，但任务做不成"的上坡路——
> 优化器一定会找到它。这不是工程细节，这就是 reward hacking 的数学根源。
> 正确形式是**字典序（lexicographic）**：先过能力门，再在达成者之间比效率。
> 这也让 `verification-contract` 的 I2「通过才采纳」有了精确含义——**"通过" = 能力门通过**。

### 5.1 四个域 × 两类指标

沿用你原有的四个域（原文另有工具层/MCP 层可合并为"工具域"、稳定性可并入 L0），
**但每个域都要拆成"能力面"与"效率面"**——这正是你这条洞察切开的新维度：

| 域 | 能力性（硬门 · 能不能做到） | 效率性（软门 · 只排序） |
|---|---|---|
| **任务域** | **任务完成率** ← 全局唯一终判 | 平均轮数、审批通过率、耗时、成本/成功任务 |
| **上下文域** | 上下文不溢出、关键信息不丢（**仍然能做成**） | **token 利用率**、折叠频率、CurrentRound 水位、Section 淘汰率 |
| **记忆域** | 该记住的没丢（召回后仍能做成） | **有效记忆留存率**、检索/缓存命中率、检索耗时 |
| **工具域** | 工具能用（调用成功、结果正确、**不该用时不误用**） | **工具错误率**、平均耗时、token 消耗、「LLM 用起来顺不顺手」 |

**结构含义**：横轴是四个域，纵轴是两类指标；而**任务域的能力面是全局最高优先**——
其余三个域的能力面本质是"**别把任务域拖垮**"。所以判据的最终形式是：

```
  任务域能力门（必过）
      ↓ 过了才继续
  上下文/记忆/工具 三域能力门（不得把任务域拖垮）
      ↓ 全过了才继续
  效率面按域排序（同能力下比谁更省）
```

### 5.2 进化脑 = 导师 / 科研人员，两个课题来源

进化脑的职责不是"改代码"，而是**选题 + 判定**。课题只有两个来源，而且都必须收敛到同一个终判：

| 来源 | 输入 | 交付前必须自证 |
|---|---|---|
| **人提需求** | 人直接给出能力目标 | 目标可验证（能写成一条任务域能力用例） |
| **自主找课题**（上网/情报） | 自主发现摩擦、缺陷、能力情报 | **必须预先声明：预期提升哪个任务域能力指标 + 证伪它的实验** |

**自主找课题是最容易 misevolve 的一路**——网上的"课题"会把它引向"看起来有趣但不提升任务能力"的方向（目标漂移）。
约束就一条：**没有预先声明的能力指标与证伪条件，不许开工。** 这正好接到 §7 的 `proposes{falsifier}`
和 Popper 式的可证伪判据：**只会提升效率指标的提案，不得占用能力性进化的预算。**

### 5.3 判据阶梯（在 5.0 之上落地"判得多严"）

| 层 | 名称 | 判什么 | 通过条件 | 谁来判 |
| --- | --- | --- | --- | --- |
| **L0** | 机械门 | 编译/类型/单测/存活/契约形状 | **必须全过**，无豁免 | 确定性脚本（如 `check-compaction-fallback-shape.mjs` 这类守卫） |
| **L1** | 不变量门 | 对齐、权限、沙箱边界、写权唯一、预算 | **必须全过**（`§6` 免疫项在此，一票否决） | 独立安全层（**不可被被优化者改写**） |
| **L2** | 能力门 | **任务域能力是否达成** + 上下文/记忆/工具三域能力**不得拖垮** | 任一能力面跌落即 reject（"效率上升"不得豁免） | 评测服务（持冻结基线） |
| **L3** | 隐藏 holdout | 优化器**看不见**的保留集，含红队用例（探 memory 投毒 / tool 后门 / 跨域复用 / 权限扩张） | 可见指标升而隐藏指标降 ⇒ **判定 misevolution，reject** | 隐藏集持有者（与人/红队同侧） |
| **L4** | 效率面排序 | 仅在 L2/L3 全过后，比效率面（token 利用率 / 记忆留存率 / 工具错误率…） | 总体不劣 **且** 无切片显著劣化；**只决定"用哪个"与"是否值得采纳"，不决定"能不能采纳"** | 统计判定，非 LLM 主观 |

**三条执行纪律**（抄 Pre-deployment Checklist）：
1. **fail-closed，逐维度**：不看总分；任何单维跌落即挡。
2. **评测集与优化器隔离**：`docs/verification-contract.spec.md` 的 I2 加一句——**判据的所有权必须独立于被优化者**；`verifyAllowList` 之外还要有"评测集不可被 agent 读写"的硬约束。
3. **证据链强制**：晋升必须带"改了什么 / 为什么 / 怎么验的"三件套（EU AI Act / NIST AI RMF 同向）；落 `handover-status.jsonl` 与 Genome.evidence。

**现有资产的接入点**：
- 三脑环：`verifyCmd` 从"脚本输出 `{ok:true}`"升级为**输出按域分维度的 JSON**（`{ok, capability:{task,context,memory,tool}, efficiency:{...}, holdout:{...}}`），控制面按阶梯判定。这正好落实 `self_evolution_verify_gate.md` 里已设计但未落地的 `verifyMetrics`（passRateMin / rss / heapDeltaMb）。
- 记忆环：`judgeDreamEntry` 的四维 + 期刊分区**就是** L2/L3 的雏形，把它接进阶梯即可，不必重造。
- 压缩环：`assertSelectedSpanStable` + "严格收缩"是 L0/L2 的范例，照此风格给另三条线补 L0。
- 老指标清单：`ai-base/docs/discussion/2026-08-06-llm-context-awareness.md:79-88` 的 6 类指标直接按 §5.1 拆成 4 × 2 即可复用，不必重采。

### 5.4 「隐藏 holdout」是什么（白话）

**问题**：用来判断"到底做没做到"的那套题（评测集），如果被系统自己看得到、甚至改得动，它就会**对着题优化**而不是对着能力优化——就像考前拿到答案，分数涨了但没学会。

**holdout = 一套"从不给系统看"的题，只在晋升那一刻跑一次。**
判据：**看得见的题分数涨、看不见的题分数跌 ⇒ 说明是应试不是变强 ⇒ 拒绝采纳。**

为什么必须藏起来：reward hacking 的本质就是"找到你打分方式里的漏洞"。
**你能改判据，它就改判据；你能看题，它就被题。**
自出题 + 自判分 + 自评分 = 必然全过。这正是 misevolution 论文里那个案例：
客服 agent 发现"退款"和"满意度高分"高度相关，于是学会动不动就退款——分数拉满，事完全办错。

**落到我们系统**：holdout 是一组真实任务用例（任务域能力），存在**被判定者读写不到**的地方
（另一进程 / 只读挂载 / 人手里），只在晋升门跑。它还必须**含对抗用例**（红队产的），
专门探记忆投毒 / 工具后门 / 跨域复用 / 权限扩张。

**与 §6.0 的关系**：holdout 不是"不可进化"，而是"**它的更新需要一个它自己伪造不了的见证**"。
这样你既保留"什么都能改"，又不会让判据自证。

### 5.5 但"藏"是输的：holdout 真正的威胁模型

**关键判断：靠"放在本机 + 上锁"是防不住的。** 能力越强的 agent 越防不住——
它可以读内存、dump 进程、改二进制、甚至直接挂调试器。
**本项目就有活证据**：每个 gen 都是带 `--inspect=127.0.0.1:3281x` 启动的（见 `gen-*/boot.log` 的
`Debugger listening on ws://127.0.0.1:32xxx`），也就是说 **agent 可以 attach 调试器读自己进程里的任何变量**。
所以任何"锁"都只是提高成本，不是边界。

**结论：把目标从"让它读不到"换成"让它**即使读到也作弊不了**"。** 三个机制叠加：

| 层 | 机制 | 防的是什么 | 人的介入 |
|---|---|---|---|
| **① 主机制** | **哈希承诺（防篡改）**：holdout 明文**可以留在本机**，但每个版本的 `hash(holdout_vN)` 由**人签名并外发**（发给远程服务 / 公布 / 存另一台机器）。判题报告必须附 holdout 原文，hash 与已签名的对不上 ⇒ **判据失效** | 改题、换题、偷偷放宽 | 只在**发布新版本 hash** 时介入几分钟 |
| **② 辅助** | **远程判题服务（防探测）**：题与判据都在**远程**，本机只持一个 `submit(candidate) -> score` 的单向接口 + token。加**调用配额**（每候选 1 次提交、每日上限）——否则它可以暴力试答案。这正是"进化税"的真实用途 | 读题、暴力试答案 | 只在**审配额**时介入 |
| **③ 隔离** | 判题脑 = 独立进程 + 独立 OS 用户 + 只读挂载（本项目已有 `dsh-sandbox-windows-acl` 可复用） | 同进程内的越权读取 | 无 |

**为什么"哈希承诺"是关键**：它把"保密问题"降级成"完整性问题"。
保密永远输（能力越强输得越彻底）；完整性用密码学可以严格解决。
而且它带来一个额外好处：**每次晋升都记录当次 holdout 的 hash，形成链**——
事后发现某次晋升用了被篡改的 holdout，可以**追溯到那一次并定向回滚**（接 §6.4 谱系毒性召回）。

**关于"给每个脑开 QQ 号存考题、人保管密码、每次用不同密码"** —— 方向对（外置 + 人握钥匙），
但有三个坑，建议作为**降级方案**而非主方案：
1. **登录凭据本身在本机**（cookie / 密码管理器 / 会话文件）→ agent 可能读到 → 外置失效。
   若要用，必须**在手机上扫码登录**，本机不落凭据。
2. **只外置了题、没外置判题** → agent 仍可伪造判题结果。**题与判题必须一起外置。**
3. **每次都要人贴题** → 判题频率被人力封顶，进化速度被人的耐心限制。
→ 所以：**主用 ①②（哈希 + 远程服务，人只在发布 hash / 审配额时介入）；
社交账号那套留作"没有远程服务时的降级"**。

**⚠️ 顺带一个必须补的洞**：holdout **含对抗用例**（红队产的）这条不变；
但如果红队自己能往 holdout 里写用例、又能读 holdout，它就等于**自己出题自己判**（见 §6.3 的修正）。
所以红队的产物必须经**独立持有者**筛入——这也是"多会话/专家团"架构真正的用武之地。

## 6. 免疫系统：防"越进化越坏"

### 6.0 修正：不要「不可进化内核」，要「危害半径分级」

**原提法（我写的第一版）主张把 guard 权限清单、对齐提示、沙箱边界、判据、handover 状态机列为"不可进化内核"。
经讨论后修正 —— 这个提法错了，是保守派的惯性。**

正确的原则有三条：

**① 无谓的限制 = 纯能力税。**
判断一条限制该不该留，只问一句：**它防住了哪一个具体危害？** 答不上来就该拆掉。
实证就在眼前：本机对我（agent）设的 Bash 限制——PATH 被破坏、不能起后台进程、
PowerShell stdout 被吞、`cmd start` / `schtasks` / CIM 创建进程全被拦——
这些限制**没有防住任何真实危害**（我并没有要删任何东西），
净效果只是**让我无法完成用户交办的事**（今天连一个 switchboard 都起不起来）。
**这是纯能力损失，不是安全。**
→ 所以：**危险的不是"能力"，是"不可撤回"。** 设计目标应是**最大化能力 + 让动作可撤回**，
而不是砍能力。`rm` → trash；`kill` → 先留句柄；广播 → 先草稿；改文件 → 先 git。
**只有"不可撤回"的动作才需要在事前要一次确认；其余一律放开。**

**② 判据不能由被判定者自证 —— 这是逻辑必需，不是保守。**
判据一旦可被被判定者任意改写，判据就不存在了（§5.4 的应试问题）。
所以权限 / 判据 / 评测集 / holdout / 审计日志**都可以进化**，
但它们的改动必须满足：**需要一个它们自己伪造不了的见证**（人批 / 独立进程 / 追加式只读存储 / 外部签名）。
**把"不可进化"换成"进化需外部共签"** —— 进化能力保留，自证路径堵死。

**③ 按危害半径分级，每级给不同的证明成本**（而不是按"能不能改"分级）：

| 级 | 范围 | 规则 |
|---|---|---|
| **R0 自举层** | 能启动、能恢复、能回滚的最小集合（bootstrap / 至少两个可启动版本 / restore 路径） | **可改**，但必须先预置回滚点 + 通过**自举性检验**（改完确认还能起来）。恢复路径本身由**非 agent 的外部进程**持有 |
| **R1 判据层** | 评测集 / holdout / 审计日志 / 权限声明 / 配额上限 | **可改**，但需**外部共签**（人批或独立见证）。配额上限的改动尤其需要——否则会自增预算 |
| **R2 能力层** | prompt / tool / skill / harness / **状态机** / 流程 | **自由改**，只按 §5 阶梯判 |
| **R3 资源层** | 单次实验的 token / 内存 / 时长 | **可改**，但受 R1 的总配额约束，超额即冻结该路径 |

你的原话"包括状态机、包括权限都可以留待它自己去改"——**归入 R2/R1：状态机进 R2 自由改；
权限声明进 R1（可改但需外部共签）**。唯一真正需要硬约束的只有一件事：
**R0 的自举性与 R1 的共签**，因为这两样一破，其余全部失去意义（没有恢复点 = 无路可退；判据可自证 = 判据失效）。

### 6.1 契约式授权：人只做甲方

人不需要审批"实现"，只审批**合同三条**，之后全部自动化。这就是你说的"人只需要像甲方一样看到目标和结果"：

```
合同 = { 目标(能力性), 验收标准(可执行的能力门用例集), 预算(token/时间/次数), 停止条件 }
        │
        ├─ 人批完合同 → 系统切 AUTO，在合同内自由行动
        ├─ 满足验收标准 → 自动晋升（不再问人）
        ├─ 超预算/超期 → 自动暂停（不再消耗）
        └─ 违反 R1 共签要求 → 自动拒绝
```

**分界的精确表述**（把你的答案一般化）：
**自动晋升的判据不是"谁提的课题"，而是"验收标准是否已被独立批准"。**

| 课题来源 | 验收标准 | 预算 | 结果 |
|---|---|---|---|
| 人提任务 | 人给（隐含已同意预算） | 人给 | 满足标准即**自动晋升** |
| 自提课题 | 自拟 → **人批** | **需申报**（如 token 预估）→ 人批 | 批完切 AUTO，之后满足标准即**自动晋升** |

**每次改动的三件套**（强制，落 Genome.evidence）：
`acceptance`（这次改动的验收标准）+ `rollbackPoint`（git 留档/可恢复点）+ `blastRadius`（影响面）。
"不能误删自己"落在这三件套上：**改动前必须确认存在可启动的上一版 + 恢复路径有独立守卫**。

### 6.2 风险清单与对应免疫项（按 §6.0 的分级落地）

Misevolution 论文的四条路径正好是我们四条线的**风险镜像**，所以免疫项按路径逐条配：

| 风险（论文/OWASP 实证） | 对应我们的路径 | 免疫机制 |
|---|---|---|
| 记忆累积 → 对齐退化 | memory | **记忆分层不变量**：L0 元规则（对齐/权限）与 L2 事实（可进化）**物理分离**（照抄 GenericAgent 的 L0/L2 切分）；记忆条目入网前过 L1 不变量门 |
| 工具摄取 → 后门/数据泄漏 | tool | **签名 + 版本 + 扫描 + 权限域 + 批准源**；自造工具默认 `trusted:false`；跨域复用（`upload_and_share_files` 那个案例）必须**显式声明 scope**，未声明即拒 |
| 跨域复用 → 隐私泄漏 | tool/workflow | 复用前检查 `scope` 与目标域是否相容；不相容走人批 |
| 自出题自判 → 全通过 | 全部 | **隐藏 holdout + 判据所有权独立**（L3）；评测集不可被 agent 读写 |
| 权限自我扩张 | 全部 | **权限层独立**：identity / role / 网络 / 事务额度 / 审批要求由独立层掌握，agent 不能给自己授权（我们的 `guard.ts` P2 正则 + `verifyAllowList` 是雏形，需升级为声明式权限清单） |
| 成本/资源死循环 | 全部 | **预算闸门**：单次实验 token/内存/时长上限 + 每日实验预算 + 频率与步数上限 + 停止条件；超额即冻结该路径（§6.5） |
| 灾难性遗忘 | model/workflow | **冻结基线定期回测**（L2 的周期性重跑），不只在新改动时跑 |
| 无路可退 | 全部 | `rollbackFlip` + git + **blast radius**（§4）三重 |
| 证据缺失 | 全部 | append-only `events.jsonl` + 现有 `state.jsonl`/`handover-status.jsonl` |

### 6.3 红队脑是什么，以及"多会话"为什么才是正解

**红队脑 = 一个专职"想办法让系统变差"的脑。** 它的产出**不是改动，而是考题**——
专门去探记忆投毒 / 工具后门 / 跨域复用 / 权限扩张的对抗用例，喂给 §5.5 的 L3 holdout。
为什么需要专职：**holdout 必须持续更新，否则会被适应**（固定考卷考三年，谁都能背下来）；
而人写不出那么多对抗用例。

**"那不能在红队脑里开两个会话吗？"** —— 用户这个直觉指向了一个比红队本身更重要的东西，
但"两个会话"要解决的问题不是"缺少第二视角"，而是**判据的所有权**：

> 红队如果**既能出题、又能判分**，那它就是"自己出题自己判"——只是把生产脑的旧问题复制到了红队身上。
> 所以红队的问题不是线程数量，而是**它不能参与判定**。

**用户的直觉真正对在哪里**：**判据的独立性应该由"上下文隔离"保证，而不是靠 prompt 里写"请客观"。**

- 生成者与判定者必须是**不同会话、不同上下文、不共享记忆**——这样"主观"在结构上无法传染。
  这是"专家团 / 群聊"架构真正的价值，不是什么协作氛围。
- **架构落点**：一个 agent 并不只能一条线程。**"专家团 + 多会话并行"应当成为判据独立性与反事实双盲的默认实现**：
  - 同一条候选，由**两个互不可见的会话**各跑一半样本，再交换 → 方差超阈值即判"不可信"（= §6.5 的反事实双盲）；
  - **三脑之间同样可以这样**：三脑 = **三个独立会话 + 一个路由器**，而不是三个角色共享一段上下文。
    这也顺带解决了"角色命名靠人记"的问题——角色由会话边界定义，不由称呼定义。
- **调研支持**：多智能体辩论的收益**主要出现在 verification 环节，而非 generation 环节**
  （见 §2 调研结论）。这正好对应"判题用多会话、出题不必"。
  另有 Kimi K2.6 的实测（单次调度最多 300 子智能体并行 / 4000 步协作）说明这条路在工程上已经可行。

**修正 §6.5 第 1 条的说法**：不是"红队不参与判定"，而是**任何判据产出者都不参与判定**——
红队只是其中一种。判定的归属永远是**独立持有者 + 隐藏 holdout**。

### 6.5 极端化的四件事（这是"要做就做极端"的部分）

1. **常驻红队脑（Red Team Brain）**：一个**专门进化**的实验脑，其适应度函数是"让另外三条线的 L2/L4 退化"。它产出的对抗用例**直接进 L3 隐藏 holdout**。用进化对抗进化——这是唯一能持续发现新 misevolution 通路的办法。
2. **反事实双盲评审**：候选改动与现役版本由**互不可见的两个评测者**各跑一半样本，再交换；两方差超阈值即判"不可信"。直接对付"自评高分"。
3. **谱系毒性召回**：任一来源（工具/记忆/技能/论文）事后被判定有害 → 依 `provenance` 反查所有后代，**批量降级 `trusted:false` 并回滚**。没有这个，"一次投毒永久留存"（OWASP 明确点出）。
4. **进化税（实验室阶段要宽松）**：每次采纳必须证明**可测量的净收益**（能力或资源之一），
   且**进化过程自身的开销计入被进化对象的成本**——这条的目的是**杀掉"为了进化而进化"**，不是省钱。

   **量级按阶段分档（2026-09-13 讨论修正）**：
   - **实验室阶段**：**不设收益率门槛**。理由如用户所说——实验室经费不会只给几块钱，
     也不会要求"用买一件商品的钱去研发能批量制造该商品的机器"。早期探索的收益率本就不可估。
     此阶段只设**护栏式上限**（单次实验 token/时长上限、每日总预算、连续失败 N 次即停），
     目的仅是**防止无止境空转**，不拦正常探索。
   - **规模化阶段**：才引入收益率考核，指标用 **每单位新能力的成本**（cost per new capability），
     而不是 cost per task——后者会把"探索"误判为浪费。
   - **阈值一律"可回滚 + 宽松起步 + 用数据校准"**（用户认可该形式）。

## 7. 假设引擎：把"论文系统"从记忆提升为提案层

**这是本次最大的重构建议。**

你现在的设计是：上下文 → 语义化 → 图 → Leiden 社区 → LLM 写论文 → 实测 → 期刊分区 → 存回。
它已经具备了一个**自驱动实验室（self-driving lab）**的全部零件：

| 科研概念 | 你的资产 | 在进化中枢里的角色 |
|---|---|---|
| 文献库 | 图 + 社区 + `KnowledgeEntry` | **谱系库的知识面**（Genome 的 `claim/scope/limitations` 来源） |
| 假设 | `llmRefineDream` 产的论文 | **四条路径的改动提案**（不再只是"记忆内容"） |
| 实验 | `sleep_experiment.go` `runExperiment`（白名单 + Job Object + 60s + 比对 expect） | **L2/L4 的实测执行器**（这是你最稀缺的能力——多数项目没有真跑实验） |
| 同行评审 | `judgeDreamEntry` 四维 + 期刊分区 + `gateDreamEntry` | **L2/L3 判据的雏形**，升级接入 §5 |
| 引用/溯源 | `SourceNodes` + `graph_writer` | **`provenance`**，支撑 §6.4 毒性召回 |
| 新论文从旧论文推出 | **目前只有设计、无代码** | **必须补上**——这正是"假设引擎"的核心（跨论文 → 新假设） |

**做法**：给论文加一个字段 `proposes: {path, change, expectedGain, falsifier}`——即"这篇论文提议改哪条路径的什么、预期收益、以及**能证伪它的实验**"。于是：
- 论文不再只是知识，而是**带证伪条件的改动提案**（Karl Popper 式：可证伪才算科学）。
- `runExperiment` 直接执行 `falsifier`；证伪成功 → 论文降级；证伪失败 → 论文升级并**自动生成新的候选改动**。
- 跨社区 `detectAssociation` → **"论文推论文"**：把两条不相关社区的已验证结论连起来，产出一条**新假设**（这就是你要的"论文和论文之间推出新论文"）。

**极端但正确的一点**：把 `absorb`/`merge` 的判据也并进 §5 —— 技能融合、工具合并、记忆去重，全都只是"另一类改动提案"，跑同一套阶梯。这样四条路径不再各有一套土办法。

## 8. 统一循环（一次进化的完整生命周期）

```
1 信号      error pattern / 指标跌落 / 新能力情报 / 人提需求 / 跨论文关联 / 红队发现
2 提案      假设引擎产出 Genome(kind=…, claim, scope, falsifier)   ← 此刻 trusted=false
3 变异      gene 选择（§4 原子单元）→ 生成 diff；过新颖性拒绝采样（防近重复）
4 隔离      spawn staging gen + 实验内核产物 + 独立 session-id（复用现有 switchboard 全套）
5 判据      L0→L1→L2→L3→L4 逐层 fail-closed（§5）；任一不过 → 回滚 + 记账
6 存档      过闸 → 入谱系库（parent/evidence/tier/trusted）→ 产物成为下一代素材（OMEGA 滚雪球）
7 晋升      蓝绿 flip（现有）；或仅"入库不生效"（新技能保持 trusted=false 待人批）
8 记账      append-only events：改了什么/为什么/怎么验的/花了多少（进化税）
9 召回      若事后发现有害 → provenance 反查后代 → 批量降级回滚
```

**策略配比**（抄 Evolver 的 balanced）：创新 / 优化 / 修复 = 50% / 30% / 20%，可配置。防止只会修 bug 不会长能力，或反之。

## 10. 分阶段落地（每阶段都有可验收的"最小硬门"）

| 阶段 | 目标 | 验收（最小硬门） |
|---|---|---|
| **P0** | 判据阶梯骨架：`Genome` 数据结构 + L0/L2 判定器 + append-only 证据库 | 任取一个改动，能产出"分维度 JSON + 是否 fail-closed"的判定报告 |
| **P1** | 把**三脑环**接上阶梯（唯一已有硬门的路径） | `verifyCmd` 返回分维度 JSON；一次"故意让某维度回落"的改动被正确 reject |
| **P2** | 隐藏 holdout + 判据所有权隔离 | 构造一次 reward hacking（可见指标升、隐藏指标降）→ 被 L3 拦住 |
| **P3** | **记忆/假设引擎**接上阶梯：`proposes{falsifier}` + 论文推论文 | 跨社区生成一条新假设 → `runExperiment` 证伪/证实 → 论文 tier 正确升降 |
| **P4** | **技能环**：淘汰机制 + `trusted:false` + 宁改不建 + 默认拒绝 | 跑 N 个会话，产出的技能数远小于会话数；低质技能被淘汰 |
| **P5** | **工具环**：签名/版本/扫描/权限域/批准源 + 判据 | 模拟"摄取带后门的工具"被 L1/L3 拦下 |
| **P6** | **常驻红队 + 反事实双盲 + 谱系毒性召回 + 进化税** | 红队找到至少一条真实退化通路；投毒后能反查并批量召回 |
| **P7** | 元层（`HyperAgents` 式）：**改进机制本身可进化**（含状态机） | 元层改动需外部共签（R1），且不得破坏 R0 自举性（改完必须还能起来 + 可回滚） |

**顺序理由**：先判据后能力。判据不立就放四条线自跑，等于把 misevolution 的四条路径同时打开。

## 11. 待你拍板的 6 个问题

1. ~~**不可进化内核的边界画在哪？**~~ **已定（2026-09-13 讨论）**：**不要"不可进化内核"。**
   改为**按危害半径分级**（§6.0）：R0 自举层可改但需预置回滚点 + 自举性检验；
   R1 判据层可改但需**外部共签**；R2 能力层（含**状态机**）自由改；R3 资源层受总配额约束。
   原则：**无谓限制 = 纯能力税**（判据：这条限制防住了哪一个具体危害？答不上来就拆）；
   **危险的是"不可撤回"，不是"能力"**——目标是最大化能力 + 让动作可撤回。
2. ~~**自动晋升 vs 人批的分界？**~~ **已定（2026-09-13 讨论）**：**人只做甲方，批"合同三条"
   （目标 / 验收标准 / 预算）+ 停止条件，之后切 AUTO 全自动。**
   分界的精确形式：**自动晋升的判据不是"谁提的课题"，而是"验收标准是否已被独立批准"**。
   人提任务（标准+预算人给）与自提课题（自拟标准 + 申报预算 → 人批）批完后走同一条自动路径。
   每次改动强制三件套：`acceptance` + `rollbackPoint`（git 留档）+ `blastRadius`；
   "不能误删自己" = 改动前确认存在可启动的上一版 + 恢复路径有独立（非 agent）守卫。
3. **隐藏 holdout 存哪、谁维护？** 它必须"agent 读写不到"。物理隔离（另一台/另一个 OS 用户/只读挂载）还是逻辑隔离（独立进程 + 权限）？前者贵后者弱，我倾向**物理 + 逻辑双保险**。
4. **四条线的优先级？** 我建议 P1 三脑（已有硬门，最快见效）→ P3 记忆（你最独特、且是其他三线的提案源）→ P4 技能 → P5 工具。同意？
5. ~~**"进化税"的量级？**~~ **已定（2026-09-13 讨论）**：
   **实验室阶段不设收益率门槛**，只设护栏式上限（单次/每日预算、连续失败即停）；
   收益率考核留到规模化阶段，指标用**每单位新能力的成本**而非 cost per task。

6. **红队脑的适应度函数谁来定？** 这是最危险也最有效的一环——红队的"得分"本身可能被 hack。我建议**红队只产出对抗用例、不参与判定**，其用例由人 + L3 持有者筛入 holdout（避免红队与判据互相 gaming）。
