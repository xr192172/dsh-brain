## 13:1x 处理掉了最后一个"从未为真的判据"：ready/追平门槛（假绿）

按纪律（**没实施过的判据级不得计作通过**）把最后一个 placebo 查清了 —— **根因是一个不存在的 API**：

- `preseed.computeCaughtUpSeq()` 依赖 `sessionPersistence.listSessions()` ——
  **上游没有这个方法**（服务名 `sessionPersistence` 是真的，方法不是）⇒ `ids = []` ⇒ 循环一次都不跑 ⇒ **恒 0**；
  另一半 `sessionProjectionCache.coldSnapshot(id).asOfSeq` **是真的**（`dsh-session-projection-cache`，profile 也装了）。
  ⇒ **171 条 freeze 里 lastSeq 全是 0** 的真正原因就是这个。
- 修法（`preseed.ts` → `liveMaxSeq(ctx)`）：只回答**能真答**的问题 —— **本进程 live 会话已落盘到哪个 seq**。
  active 代报真数；刚拉起的 staging 代报 0（**诚实**：它还没加载任何会话）。
- ★ **耦合陷阱**（差点自己造一个新 bug）：只改 preseed 会让 active 代报真数、staging 代报 0
  ⇒ 原来的 `waitCatchUp(b, targetSeq)` 会**白等 40s 然后 abort 每一次换代**。
  所以必须同时把 ready 门槛从"比 seq"换成**结构性就绪**（`waitReady`：进程活 + admin 应答 + gen 名一致），
  `waitCatchUp` 降级为**只用于 1.5s 有界观测**（注释里写明"不得用作推进门槛"）。
- 门：`test-handover-drain` 加 B2/B3/B4 四类断言（进度读数走 `liveMaxSeq`、preseed 不再碰 `listSessions`、
  ready 走 `waitReady` 且不再有 `waitCatchUp(b, targetSeq)`）⇒ **41 项全绿**；`check:all` 15/15；已构建。

**又踩到一次"判据读文本"的坑（已修并记进技能）**：我把旧 bug 的名字写进了 `preseed.ts` 的**注释**，

### 订正后的三段流水线

```
① 进化脑【发现 + 提 PR】   —— 选型 skill / 对比现有能力 / 发现进化点；只提案，不产代码、不融合
② 评审团【评审 PR】        —— 多模型讨论；审"这个 PR 值不值得做"
③ 开发脑【完整开发】★      —— 把 PR 提到的工具**全都打包好 + 融合好 + 测试好**
④ 【回传】                 —— 交付回能力库
⑤ 【根据数据重新来过】★    —— 整个循环是**数据驱动迭代**
```

★ **别名**：用户口语里 **"开发脑" = "生产脑"**（同一角色）；**"评审团" = "专家团"**。已写进 §5.1。

### ★★ 核心机制：围绕「能力面」的三种操作（这是最实质的一句）

| 能力面关系 | 操作 | 产出 |
|---|---|---|
| **不同**（不重叠） | **新建子 agent** | 各自**自己的职业准则**（=`SubagentProvider` 的 `persona` / 职责边界） |
| **相同**（重合） | **合并** | 一个（`SkillNode.Absorb`/`AbsorbOutcome` 是现成字段） |

⇒ **Skill 树 = 这套操作的对象与账本**；新子 agent 不断长出来，能力面决定"新建/合并/融合"。
