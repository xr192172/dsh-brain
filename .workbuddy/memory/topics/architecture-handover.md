## 0. 一句话

**把三脑那套"人脑分工"落成可运行的三个角色**：**发现席（进化脑）／解决席（开发脑）** 两个
`SubagentProvider` + **顶层的评审团编排**，跑通「**提 PR → 评审 → 完整开发（打包/融合/测试）→ 回传 → 按数据迭代**」。

---

## 1. 现状盘点（2026-09-20 实测，逐格）

| 角色 | 形状 | 现有 | **缺** |
|---|---|---|---|
| **进化脑**（发现 / 提 PR） | 独立子 Agent | `capability-registry` 有 `lineage`（注册/升级/合并/淘汰）+ `supersededBy`；`SkillNode`（技能树）**未移植** | ★ **这一格基本是空的** —— 选型 / 对比 / 提 PR 全都**没有实现** |
| **开发脑**（完整开发 / 融合 / 测试） | 独立子 Agent | `ctx.subagents.registerProvider()`（`subagent-council` 已示范）+ `capability-registry register` + `tool_apply` 可激活 | **独立的"开发席"provider**；**融合执行器**；把 PR 里工具"打包"的路径 |
| **评审团**（评审 / 裁决） | 顶层（多模型） | 注册门 **L0/L1** + `check-all` 15 门 + `eval-run` + 基线表 + `subagent-council`（已有 provider 骨架） | **L2~L4**（⇒ 见 `tool-refinement-handover.md`）；**holdout 的持有与隔离**；多模型讨论编排 |
| **隔离被测** | 单独的工具 | profile 已有 `sandbox: read-only` + `dsh-fs-sandbox` | 与流水线的接线 |

**★ 三条不可越过的约束（来自已定案，别自行改）**：
1. **发现席与解决席必须是两个独立 provider**（**防串供**）—— 不是同一个 agent 的两个工具。
2. **审批权只在评审团** —— 开发脑只有"**自证符合标准**"（标准由评审团在提任务时给，**不是自己拟的**）。
3. **融合的判据是分级（字典序），不是加权** —— 无回归 / 新功能节点是**硬门**，效率只是**排序**。

## 2. 依赖关系（**开工前先看这张，决定先做什么**）

```
靶场线（M1）  ──供给判据数据──▶  工具完善线（L2~L4）  ──供给效果判据──▶  架构线（本文）
   ↑ 另一会话在做                    ↑ 已派                                ↑ 本文
```

**⇒ 但架构线有两条腿，其中一条现在就能走**：

| 腿 | 依赖 | 现在能开工吗 |
|---|---|---|
| **① 数据层**：移植 `SkillNode` 技能树（`sqlite_store`/`graph_cache`/`rrf`/`gravity_field`…） | 无 | ✅ **能** —— `design §13`：「**数据先行、执行器可替换（P2 数据 → P3 执行器）**」 |
| **② 执行层**：两个 provider + 流水线编排 + **融合的判据落地** | **L2~L4**（工具完善线） | 🟡 **骨架能开工**，判据部分**等** |

> ★ **一个看似矛盾的顺序问题（已想清，别被绕进去）**：
> - `master-plan` §10 说「**先判据后能力**」（否则四条线自跑 = misevolution 四条路径同时打开）
> - `design §13` 说「**数据先行**」（技能树内部：先接数据模型，再换执行器）
>
> ⇒ **两者不冲突**：**"判据先行"是全局节奏**，**"数据先行"是技能树这条线内部的顺序**。
> ⇒ **正确做法：全局上补齐 L2~L4，同时开始移植 Skill 树数据模型。两者并行，互不阻塞。**

## 5. 验收（最小硬门）

- **两个 provider 可独立起、可委派、结果可回流**（照 `subagent-council` 的既有形状）；
- **一次完整三段流水线跑通**：进化脑产出 PR → 评审团给出结论 → 开发脑产出（含融合/测试）→ 回传；
- **审计可查**：每一段都有留痕（委派档案**写入时外置化**，见 `design §9 ①`），
  且能回答"这个子 agent 是谁、按什么准则、过了哪些门"；
- ⚠️ **判据未实施就标 `unenforced`** —— **不许把未做的级标成通过**（本项目最贵的教训）。
