⇒ **数据与日志分家**，而两边各自都"正常" ⇒ **沉默**（最坏形态）。这就是 R1 盘查 §2.4 的影子依赖。

### 14.2 怎么修的（方案 A，**不是**补丁）

1. `resolvePlacement(home)`（`main.ts` 新增）
   —— **单一求值点**：`WORK_DIR` 全文件只读一次；`coordDir`/`workDir`/`genAssembly` 全从它派生。
2. **分裂则拒启动**：`WORK_DIR` 被显式设置且**不在 `home` 之下** ⇒ 报错 + `exit(1)`，
   把"为什么这是坏的"逐字打出来。逃生阀 `ALLOW_SPLIT_WORK_DIR=1`（会警告留痕）。
3. **四值指纹**：启动打印 `[switchboard] placement: home=… workDir=… genAssembly=…`
   ⇒ "这代到底看的哪份 home"**不再靠推**（铁律 12/15）。
4. config 四值全部改成取自 `placement`。

★ **否决的方案 C**（"检测到不一致就自动纠正成 home 派生值"）：**静默纠正比静默分裂更坏**
（让人以为设了有效，实际被改掉；同铁律 9"静默坏比崩更隐蔽"）。

### 14.4 ★ 实施中门自己抓到的一件事（值得记）
